# 小窗 XIAOCHUANGx 0.1.6 更新说明

0.1.6 是 Desktop Alpha 的对话结果与处理过程体验收口版本。当前候选包为 `0.1.6-rc.3`，最近正式基线仍是 `0.1.5`。

## 主要更新

- AI 执行期间默认展开处理过程，按真实发生顺序连续显示业务旁白、读取、搜索、命令、修改和阶段性业务产出。
- 每次可见思考独立形成业务说明节点，并与对应搜索、读取和命令按发生顺序交错；不再把整轮思考汇总到消息底部。
- 文件、命令等动作证据在运行中直接展开；任务完成后复盘时默认收起，点击动作摘要即可查看具体文件和命令。
- 最终回答开始输出时，处理过程只自动收起一次，并切换为“已处理 + 耗时”；用户之后的展开或收起不会再被系统覆盖。
- 助手消息固定为“处理过程 → Outcome → 最终回答 → 交付物”，过程内容不再切断或重复最终回答。
- waiting_user、失败、中断保持展开，原因、恢复动作、部分结果和交付物不会被隐藏。
- requirements、需求摘要、大纲和推演阶段产出作为业务 checkpoint 进入过程时间线，不再与最终回答争夺结果区。
- Codex、Claude 与 Hermes 通过向后兼容的 `assistant.segment` 事件区分 `pending`、`process` 和 `final`；Companion SSE 为旧客户端合成带兼容标记的 final `message.delta`，新版客户端只渲染一份正文。
- 用户展开过程、切换最终回答或阅读长正文时保持视口稳定；运行中的过程条继续与用户问题组成 sticky 栈。
- 390px 移动宽度自动折叠侧栏，过程摘要、正文和输入框不再被固定最小宽度裁切。
- 提供 `CHAT_ACTIVITY_V2_ENABLED=false` 快速回滚开关，可恢复 0.1.5 交错时间线，无需迁移消息数据。
- 修复 Desktop 使用隔离 Next.js 构建目录打包时静态资源落入错误路径、启动后登录页白屏的问题。
- 修复 Codex 未携带消息 phase 时把每段过程说明误判为最终回答的问题；未定文本通过 `pending` 生命周期在动作或 Turn 结束时原位提交。
- Desktop 内嵌 Web 改用稳定 Origin，并在新 Origin 首次启动时从 Companion 恢复最近 24 小时的会话入口；重启不再丢失侧栏任务、Agent 和工作文件夹选择。
- Desktop 启动时若 Companion 晚于 Web 就绪，会按有上限的退避策略重新探测 Agent，不再长期停在“连接中 / 无可用通道”。
- Hermes 终端失败只展示一条用户可读错误，不再同时追加原始错误与二次包装错误。
- 修复默认工作文件夹中的只读终端命令被误判为交付物、进而触发 `lazy_workspace_no_generated_files` 并把已完成任务标为失败的问题。

## 候选版验证

- 75 个 Activity、Turn、parser、交付物真实性与分段缓冲 fixture 通过，包括历史 Run Event 重放、`part.patch` 保序、Session 折叠所有权、Codex 未标注 phase 的 pending 提交、命令 output、Hermes CLI 错误去重和只读路径不生成虚假交付物。
- 23 条 chat Playwright 回归通过，覆盖实时展开、完成态复盘、等待/取消、滚动锚点、sticky、移动端、附件、大纲、工作区链接、新旧双事件去重、纯旧 delta、近期会话恢复、终端错误去重和启动探测重试。
- 1440×900、1024×768、390×844 三档视口完成截图评审，未发现过程区文字重叠或页面横向溢出。
- Codex 0.144.3、Claude Code 2.1.161 与 Hermes Agent 0.18.2 真实工具任务通过；SSE 与 Run Events 顺序一致，Session 正文与 canonical final 一致。Hermes 0.18.2 Gateway 只提供工具身份、状态和标签，不提供 input/output，界面保持真实降级而不伪造载荷。
- 写作/PPT、3D、视频与推演结构化 UI 门禁通过；Contracts、Runtime Core、Companion、API、Web、Desktop 与 Video 构建/类型检查通过。
- 本机 macOS arm64 解包候选构建通过，版本、ad-hoc 签名结构、Web bundle、Companion bundle 与 Skills 资源已核对；打包流程会实际启动 prepared server，检查 `/login` 及页面引用的全部 CSS/JS，普通模式启动也已完成可见窗口验证。
- RC3 面向内部测试：macOS 使用 ad-hoc 测试签名，Windows 使用未接正式证书的 NSIS 测试制品。Developer ID、Apple 公证、Windows Authenticode 与 SmartScreen 信誉不作为本轮阻断项。

## RC 验收重点

- 使用 5～8 个真实长任务完成内部可用性验证，确认用户能理解 AI 当前在做什么，并能快速定位最终回答与交付物。
- 安装最新 macOS ad-hoc 与 Windows NSIS 测试候选包，检查版本号、启动、历史会话、真实 CLI 和回滚开关。
- RC 验收通过前不创建 `v0.1.6` tag，不将候选包标记为正式发布。
